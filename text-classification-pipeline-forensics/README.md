# Topic A: Text Classification Pipeline Forensics

CPU-only text classification pipeline for the Kaggle Disaster Tweets dataset, built for
the five investigation tickets described in the assignment handout.

## Setup

```bash
/opt/anaconda3/bin/python -m pip install pandas scikit-learn scipy
```

## Data

`data/train.csv` is the public Kaggle Disaster Tweets labeled data, mirrored from
`https://github.com/ucbrise/kaggle-nlp-disasters`. `data/split_indices.json` is the
fixed, provided split (seed 3102) -- it is not regenerated by any script here.

To (re)download the data:

```bash
curl -sL -o data/train.csv \
  "https://raw.githubusercontent.com/ucbrise/kaggle-nlp-disasters/master/data/train.csv"
```

## What each ticket script does

- **ticket1_baseline.py** -- trains TF-IDF + Logistic Regression on `train_ids`,
  evaluates on `heldout_ids`, and compares to `configs/project_contract.json`.
  Runs two variants: a naive-default config (bigrams, sublinear TF, C=1.0) which
  misses the reference by -0.0134 F1, and a reference-reproducing config (unigrams
  only, no sublinear scaling, C=2.0) which matches within tolerance (+0.0002).
- **ticket2_normalization.py** -- compares 5 named normalization configs
  (`pipeline/preprocess.py: CONFIGS`) on dev only, freezes the best, evaluates once
  on heldout, and reports exactly which ids flipped from wrong to right (or vice versa).
- **ticket3_shortcuts.py** -- trains keyword-only and length-only models to measure
  shallow-feature signal in isolation, compares to the full text model, and flags
  near-pure keyword/target correlations as a possible dataset artifact.
- **ticket4_decision_rule.py** -- sweeps threshold 0.30-0.70 on dev, compares
  `class_weight='balanced'` vs `None`, trains a second CPU classifier (linear SVM via
  SGD), picks the best dev candidate, and reports the heldout FP/FN tradeoff vs
  Ticket 1's reference-repro baseline.
- **ticket5_data_quality.py** -- finds exact-text duplicates with conflicting labels
  (train only, proposes fixes but never edits data), near-duplicate templated tweets
  with label disagreement (all splits, reported only), and high-confidence heldout
  errors ("hard negatives", reported only -- heldout labels/examples are never edited
  or removed).

## Output artifacts

- `predictions/heldout_predictions.csv` -- `id,y_true,y_pred,score,model_name,ticket`
- `results/summary.csv` -- per-ticket summary with FP/FN deltas and decisions
- `results/threshold_sweep.csv` -- precision/recall/F1 at each swept threshold
- `results/data_quality_audit.csv` -- `id,issue_type,evidence,disposition,confidence`

## Reproducibility check

After regenerating artifacts, run this one-line check:

```bash

```

Expected output:

```text
pred 7615 0
summary 6 [1, 2, 3, 4, 5] 0
sweep 9 0
audit 43 0
```

environment. Those warnings do not affect the metrics or generated artifacts.
